# Contributing

We are still in the early stages of development, so we'd love you to jump in casually.  
We keep rules to a minimum and only ask for the basics to be shared.

## First Things First

- Small fixes (typos, tiny UI tweaks, README updates, etc.) are welcome as quick PRs
- For larger changes, a short heads-up in an Issue or Discussion helps things go smoothly

## Branch Names

No strict rules.  
Any name that makes sense is fine.

Examples:
- `fix/login-bug`
- `feature/comment-filter`
- `chore/update-readme`

## Commit Messages

Any format is fine.  
As long as it's clear what you did, it's good.

Examples:
- `fix: avoid crash when video is missing`
- `update UI copy`

If needed, we'll squash or tidy things up when merging.

## PR Notes (Minimum)

As long as these are clear, it's enough:

- Purpose (what you wanted to solve)
- Changes (what you changed and how)
- Scope (UI/DB/API, etc.)
- Verification (whatever you were able to check)

If your PR touches the UI, screenshots or a short explanation are appreciated.

## Changes That Likely Need a Quick Consult

Please consider a short discussion beforehand if your change includes:

- Large feature additions that affect behavior or specs
- DB schema changes or new migrations
- API changes that could break compatibility

## Code Style

Please follow the existing style and structure as much as possible.  
Comments are helpful as light notes on complex logic or parts where intent is easy to miss.
